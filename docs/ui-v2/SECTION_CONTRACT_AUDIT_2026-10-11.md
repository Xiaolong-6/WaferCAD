# Section: M2 vs legacy controller contract audit — 2026-10-11

Scope: **read-only source audit**, no runtime/browser validation. Compare `site/ui-v2/mock-views.js:viewPanel('section')`, `site/ui-v2/mock-workspace.js:openViewSettings/handleAction`, and `site/ui-v2/section-legend.js` against live controllers and the D1 native adapter. ## Render/runtime boundaries

- Use **one** `model`, `section`, `sectionViewport`, `sectionDetailRoi`, `sectionCollapse`, and shared scheduler; independent from Main/Mask viewport transforms.
- `plan-renderers.js:createPlanRenderers.renderSection` is already a **public return method**. `renderSectionDetail` is also public. Its factory takes callback dependencies and renderer IDs; bind them to newly built v2 canvas/controls, **not cloned legacy DOM**.
- `section-view-viewport.js` is display-only; stored geometry remains µm. `app.js` currently injects view state into D1 bridge, which **must be replaced** by new v2-owned state (no `app.js` boot).
- The M2 “Equal-band stack schematic” is mock illustration only. Render the actual Section compositor and its physical scaling, material visibility, slice updates and Z collapse.
- D1 gesture adapter is **an integration reference, not a standalone runtime**: it currently depends on bridge callbacks registered by legacy `app.js`. Carefully transfer/adapt those callbacks, not the page or DOM.
- In the visual kit, use existing `view-kit/` floating-strip/editor/fields/gestures as configurable building blocks; no Section-specific fork.
