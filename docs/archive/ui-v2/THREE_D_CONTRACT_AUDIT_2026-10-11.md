## Real interaction audit / outstanding contract

1. `three-view.js:createThreeView.init` creates **one** `OrbitControls(camera,renderer.domElement)` and registers start/change/end to adjust rendering quality, rough refinement and camera-state callback. Do not interrupt its lifecycle inadvertently.
2. `three-view.js:createThreeView` returns `init`, `render`, `fit`, `getViewState`, `setViewState`, `updateZCollapse`, `exportGlb`, `capturePng`, `ready`. **No public enableRotate / setMode / wheel gate** is currently exposed.
3. `ui-v2/real-three-controls.js:create` has private `mode`, `setMode`, `begin/move/end`, `moveCamera/zoomCamera`; it uses capture-phase interception and `stopImmediatePropagation`. Current modes are `null|pan|zoom`. Default OrbitControls left-drag rotates and wheel zooms. This **does not yet satisfy** the requested exclusive Rotate/Pan/Zoom + Zoom-gated wheel contract.
4. On desktop, requested: Rotate on by default; selecting another tool turns the previous off; left-drag follows selected tool; wheel zoom only when Zoom active. Touch: one finger follows tool, **two-finger pinch always zooms**. Verify cancellation/pointer capture and interaction between D1 capture listener and OrbitControls touch controls.
5. There is **no evidence** that M2's presentation-only global `state.tool` accurately reflects 3D gesture mode: `mock-workspace.js:handleAction('tool')` writes a shared label and explicitly says gestures are unavailable. The combined runtime must own per-view tool modes, not copy this fake shared state.
6. `app.js:initThree` wires `getModel`, `getClipGeometry`, `getInspection`, `getZCollapse`, `onViewChanged`. Recreate this dependency injection from **one independent v2 runtime**; `app.js` must not boot and legacy DOM must not be cloned.
7. 3D/Section Z Break relation: `app.js:createSectionCollapseController.onChanged` calls `threeView.updateZCollapse`, `onSettled` calls `renderThree`; reuse `three-view.js:updateZCollapse`. Do not add renderer-specific Z recomputation in the adapter.
8. Fit/rotate/zoom/ROI and viewport changes can affect adaptive LOD / scene caching; acceptance must check actual WebGL backend and full model sameness separately from visual parity. No renderer rewrite in this stage.
