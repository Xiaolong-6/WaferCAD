## Interaction changes

1. **Step mode:** The former six-button Deposit/Extend/Etch/Implant/Electrical/Record grid becomes a single native `#operationType` select. The existing Process controller, target/area/coverage fields, History editing and Recipe replay continue to use the same operation values. `#operationTools.dataset.operationMode` supplies the view-level styling contract where formerly CSS used a button's active state.
2. The successful-Step recording preference remains the existing `#recipeRecordManual` control and defaults to its pre-existing value, but its label is now **Also add to Recipe** next to Apply.
3. The contextual Before/After Process guide remains dynamically generated by the same catalog/SVG functions but is now a collapsed-by-default `<details>` disclosure. Its explanatory text and link are inside the disclosure.
4. **Recipe:** The name and template selector lead into a preview instead of instantly calling `persist()`. Load explicitly commits an empty/default Recipe; replacing existing steps, an edited name or an unapplied Code draft requires a second **Replace Recipe** click. Cancel never commits changes. The previous Recipe stays in the existing bounded in-session Undo stack; Stop appears only while a run is active.
5. The Recipe editor groups **Build**, **Check** and **Run**, caps the scrolling step list and keeps a compact sticky run footer. The Process worker and geometry kernel were not changed.

## Data safety boundary

Template choice only updates transient preview state. The actual Recipe and model/History are not changed until explicit Load/Replace. `normalizeProcessRecipe`, project I/O schema and Recipe run preflight are unchanged. **Recipe Undo is session-local.** A dedicated persisted Recipe version archive or Recovery backup is future work; the UI says explicitly that the previous Recipe cannot be undone after reloading.
