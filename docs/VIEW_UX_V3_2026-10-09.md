# View UX v3 — four-view interaction contract (2026-10-09)

> Implementation and acceptance handoff for `feat/view-ux-v3-unified-20261009`. This records design rules, implementation scope and evidence boundaries. Never treat a syntax/static check as screenshot or browser acceptance.

## Design contract

Every Main, Mask, 3D and Section header has (1) a semantic view/mode selector when applicable; (2) 2–3 high-frequency tools; (3) Display where the view has appearance controls; (4) More for zoom, export or lower-frequency tools; (5) Max/Restore only when applicable. Menus are built with the original DOM nodes and IDs, without parallel command copies.

| View    | Always available                   | Display               | More                                                                               |
| ------- | ---------------------------------- | --------------------- | ---------------------------------------------------------------------------------- |
| Main    | Slice, 3D ROI, Pan, Fit            | —                     | Zoom −/+, Export SVG, responsive overflow                                          |
| Mask    | File/Draw selection, Mask ROI, Fit | mask opacity          | Zoom −/+, Export SVG/GDS/OAS (cells/layers remain selectable), responsive overflow |
| 3D      | Fast/Quality selection, Fit        | layer opacity, Border | physical GLB / rendered PNG export, responsive overflow                            |
| Section | Auto/1:1 X:Z, Z Break              | structural Border     | Detail ROI, SVG export, responsive overflow                                        |

All views share the same selected-state palette. A **Mode** reports the current option and switches directly via select. A **Toggle** reports a persistent state via pressed/checked, without ON/OFF badges. A **Popover** reports only its open/closed state; its closure does not disable the feature. A one-shot **Action** closes More on activation. A canvas pointer-down or Escape dismisses popovers without changing model data. Display and More controls are visually consistent but view-specific in content.

Viewport adaptation uses each actual view-panel width (ResizeObserver), not only the whole browser width. `view-toolbar-controller.js` moves the **original** control between its header and the per-view More area using a placeholder; no duplicate events/IDs are created. The existing Mask drawing toolbar remains contextual to Draw mode. Main 3D ROI, Mask Process ROI and Section magnified Detail ROI are separate concepts and labelled accordingly.

## Section Z-axis break

The former axis-floating interactive button and hidden double-click enable/disable are deleted. `Z Break` in the Section header always opens the editor, including when the break is disabled. The editor has an explicit Enable checkbox, directly editable upper/lower physical Z boundaries, a draggable snapping ruler and a collapsed Advanced section for relative Front/Back weighting. Fine target, Step and ± controls are replaced by direct numeric input.

The Section Auto display can use the Front/Back weights, while physical 1:1 X:Z displays retained regions at a common px/µm scale. The relative weights still inform 3D. This mode-specific difference is explained inside Advanced. No Kernel geometry or physical-export transformation is modified.

The Z Break editor is now a native dialog with two presentations sharing one DOM subtree and one controller. In a sufficiently large Section canvas it uses a bounded, inline, non-modal editor. Whenever the Section body is narrower than 420px or shorter than the actual editor content (minimum 380px), the editor is promoted to the browser's top-layer modal and temporarily portalled into `document.body`. This also works when Section is collapsed: it does not depend on a visible canvas parent. Its controls and advanced options are no longer squeezed into a second scrolling panel in the dock. The modal has one bounded scroll surface only on extremely short viewports, a backdrop, Escape and explicit Close; closing restores the editor to the Section overlay. Section's separate Layers legend retains its dock layout and never has to expand to make space for the editor.

## Maintainer architecture

- `site/app.html`: semantic toolbar controls and the rebuilt Section editor; keep controls uniquely identified.
- `site/controllers/view-toolbar-controller.js`: the sole breakpoint/reparenting policy.
- `site/controllers/view-popover-controller.js`: the sole view-popover dismissal and ownership policy.
- `site/controllers/section-collapse-controller.js`: open state, enabled state, bounds editing and advanced scaling; never conflate these three state dimensions.
- `site/style.css` and `site/workstation.css`: shared light/dark control tokens and bounded popover shells; avoid introducing another per-ID selected palette.
- `site/controllers/draw-mask-controller.js`, `workspace-actions-controller.js`, `plan-renderers.js`: explicit current-mode synchronization; never flip mode in response to an ambiguous label.
- `site/section-z-collapse.js`: canonical unchanged display transform; Section Auto, physical 1:1, 3D and SVG/GLB must maintain their scientific contracts.

For any new view action, first classify Mode, Toggle, Popover, Action or Tool; place it into the existing hierarchy and add a scripted interaction/screenshot assertion. Do not introduce an additional direct header button merely for emphasis.

## Self-audit and validation gate

Source-level preflight checked the four-view HTML for matched tags/unique key control IDs and syntax-parsed changed JavaScript modules (16/16 at the audit snapshot). We also inspected actual controller call sites and removed old double-click, Fine target and mode-cycling code. Issues found during review and corrected include incorrectly bottom-anchored popovers, menus exceeding split-panel height, nested panels that would overflow More, and menus covering the canvas after a one-shot tool action.

## Product-level acceptance follow-up (2026-10-09)

A structural review after PR #158 was already merged exposed a practical defect: the Section editor was confined to the shallow Section canvas with an internal scrollbar. The adaptive dialog implementation replaces that coupling rather than adding another overflow override. The browser acceptance script now captures the open editor in desktop, split and phone layouts, asserts viewport containment, requires the modal path when the Section is too small, exercises disabled/re-enabled state and Escape, and records each visible view panel separately.
