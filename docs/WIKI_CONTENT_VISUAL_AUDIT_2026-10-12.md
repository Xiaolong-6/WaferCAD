## Editorial rule

Every illustration must answer a specific question in the adjacent paragraph. Prefer, in order:

1. A **matching WaferCAD capture or shipped example thumbnail**, tied to the exact named example and with a caption saying what it actually demonstrates.
2. A **canonical in-app Process Guide schematic** for the named operation, explicitly labeled conceptual and not a screenshot or fabricated physics result.
3. A **task-specific Mermaid diagram** for selection logic, workflows, view relationships or troubleshooting where a screenshot would obscure the important facts.

Do not add stock photography, random microscopy, generic semiconductor renders, unrelated device previews or purported research-article figures simply to increase illustration count. Original publication figures require appropriate usage permission, attribution and explicit figure provenance. Caption each image immediately below it, identify the source/type (actual app output vs. schematic vs. workflow logic), and explain scientific/visualization limitations. Figure alt text must describe the example or mechanism, rather than repeat “sample image.”

- The **eight** Welcome entries were checked against `BUNDLED_EXAMPLES`, not a handwritten count.
- The **19** operation illustrations are generated from `PROCESS_GUIDE`; they are scientifically scoped schematics, not screen captures.
- The live v2 UI owns current button names. Legacy UI controls are only mentioned explicitly as legacy equivalents; Process Recipe Code remains a restricted literal language.
- The previous filename/path-only audit missed a severely blurred UI image. This correction included actual **raster byte retrieval and image inspection**: repository JPEG preview assets (480 × 300-class) are too blurry for instructional use; eight bundled 640 × 560 WebP example covers depict real geometry but contain too little detail for full-size UI demonstrations. The MAGIC-1000 Section thumbnail (920 × 600) is usable for shape discussion, and the older Windows baseline (1384 × 239) illustrates actual Section geometry only as **dated Legacy UI evidence**, not today's UI.
- One legacy JPEG did not decode in the image inspection renderer; it is not embedded in the active manual. These old assets are left untouched for their original application/revision uses. This audit does not establish that old screenshots match the current shipped UI.
- No visual baseline, source-science code, Process Guide generator, third-party photo, workflow trigger, example geometry or product UI was changed as part of the Wiki edits.

- **Scope:** reviewed all 138 tracked Markdown documents for embedded Markdown/HTML images; the active Wiki now embeds **40 image occurrences** across its 15 Markdown pages plus **12 task-specific Mermaid diagrams**. The 40 occurrences refer to 19 unique generated Process SVGs, one four-meta-atom SVG, eight shipped WebP output previews and one dated Section PNG reference (repeated across pages). The root README now uses a view-relationship diagram rather than an over-enlarged 3D thumbnail.
- **Raster asset inspection:** retrieved and viewed the repo's eight example WebP thumbnails, legacy JPEG preview family (three visible but low-quality and one failed renderer decode), five Windows visual baselines, five historical `docs/review/` captures and four Stage B review PNG captures. Legacy captures are sharp enough to preserve as **historical evidence** but depict interfaces that differ from the current v2 workstation. Do not insert them in current-control tutorials.
- **Specific rejected image:** `site/example-previews/visualization-mask.jpg` is about 480 × 300 pixels and very blurred. It does not permit identification of Cell, Layer/Datatype, Mask source or selection state. Removed from `AI-Assisted-Workflows.md` and `Masks-and-ROI.md`; the original `site/` asset was not altered.
- **WebP cover policy:** bundled example covers at 640 × 560 px can identify the corresponding project in a catalog. The small/distant rendered object and large margins make them unsuitable as enlarged figures explaining a workstation action or a detailed physical interface. Keep them adjacent to **their own named examples**, with actual-output/reconstruction caveats.
- **Useful Section references:** `magic-1000-mos2-beol-section.webp` (920 × 600) shows a readable reconstructed layer stack and Z-break. `photodetector-section.png` (1384 × 239) shows a dated scientific section with old interface chrome; keep with its explicit baseline date.
- **Generated Process SVG review:** each of the 19 SVG files has a scalable 500 × 174 viewBox, BEFORE and AFTER labels, two 220 × 124 geometry panels and self-contained shape primitives; none embeds raster photography or loads external images. Sources were inspected, including Conformal, Selective Etch, Lift-off and Conformal Extend geometry. The original auto-generated files were not hand edited. This is **source-structure** review; actual deployed SVG rendering still requires a browser check.
- **Meta-atom SVG:** the TiO₂ example vector source contains circle, square, annular ring and ring-plus-center geometry with an explicit SCHEMATIC ONLY statement, and is appropriate only for that specific example/Workflow C.
- **Image placement rules:** do not count image file existence as quality acceptance; verify actual content, legibility at intended display size, corresponding model/task and whether a captured UI still reflects the shipped version. If the only available screenshot is unfit, omit it and explain the operation with a genuine Process SVG, Mermaid diagram or precise text instead. Never substitute AI-rendered semiconductor art for real WaferCAD output.
